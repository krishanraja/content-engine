## Why Claude and Codex did not behave the same

**Verified difference in execution surfaces.** Claude Code reads this repository's [`CLAUDE.md`](../../../CLAUDE.md), which imports `AGENTS.md` and adds a mandatory first step (`scripts/check_failures.py`), explicit `/make-piece` and `/produce-video` routing, an Opus/Sonnet division of labour, a pre-push `npm run verify`, and a full-size watch-and-listen instruction. Its [settings](../../../.claude/settings.json) run pre-tool publication, taste, secret, board and cost guards plus stop checks. This Codex chat received `AGENTS.md` and the account-wide skill catalog, but the catalog did not expose the repository's `make-piece` or `produce-video` skills as invocable entries, and Claude's hooks do not execute in Codex. Those are concrete differences; they do not prove that Claude would have made every creative call correctly.

**Codex also failed within the shared rules.** `AGENTS.md` already says to start with the workbench, run the failure check, route video production through the repository skill, preserve the publication boundary, and make every visual explain a critical point faster. The missing Claude hooks cannot explain away ignoring shared instructions or persisting with weak visual judgment. This is an execution failure as well as a client-parity gap.

**A green register was weak evidence.** On 24 October `python scripts/check_failures.py` reported 35 guarded failures and none open, plus 50 encoded learnings and six open. Its [implementation](../../../scripts/check_failures.py) checks that a named file exists and contains a marker string; it does not execute an adverse example or inspect a finished video/article. The [video delivery gate](../../../scripts/quick-edit/quality.py) checks exact hashes and required receipt fields, including `heard`, motion and full review, but the published video now has reported chopped speech. A receipt can be complete while its listening judgment is wrong or insufficient. The [Wednesday readme](README.md) records 67.7% and 51.5% measured shake reduction and six passing sync windows; these are valuable measurements with a narrower scope than “good video.” The prior `cut-called-done-unheard` entry in [`config/failures.json`](../../../config/failures.json) is especially relevant and must be tested against this new incident rather than accepted as closed because its marker exists.

**Model choice is not a proven root cause.** Claude Code is configured for Opus on judgment and Sonnet on production; this task used GPT-6 Sol. There was no controlled run with identical source pack, skill loading, prompts, review points and scoring. It is fair to say Claude's workflow had more repository-specific routing and automatic enforcement, and Codex's observed delivery was worse. It is not possible from this incident to assign a numerical share of the failure to the base models.

## Safeguards that go beyond instruction parity

These are proposed controls, not changes already made. They address ways a conscientious Claude run could also miss a bad final asset.

1. **Release manifest and state machine.** Give each deliverable one immutable export hash and an explicit state: `draft`, `review`, `accepted`, `published`, or `withdrawn`. Make “board ready” a computed state: every required asset must have a current editorial review tied to that exact hash, a delivery check, and Krish's still-current decision. A newer withdrawal or changed export invalidates prior approval automatically. The board should show these states; a narrative handoff must not be able to override them.
2. **Cut-level audio inspection.** On every rendered video, enumerate actual edit boundaries, decode audio around each one, and compare the spoken track with the accepted continuous source. Flag missing or truncated phonemes, abrupt waveform/spectral jumps, and gaps for a human listen at each boundary. Run this on the final encoded file, then compare it byte-for-byte with the board download and, if accessible, the public upload. This would target the defect that escaped six sampled sync windows. It still needs human listening; an automated pass cannot certify natural speech by itself.
3. **Visual regression against a real reference.** Store a small set of approved prior-board covers and article figures as reference examples with brand invariants: identity mark, logo scale, safe area, type alignment, density and mobile legibility. Test representative frames of each final export and all image formats at actual display sizes. A hash check only proves the right file arrived; this check asks whether it still belongs to the channel.
4. **Adversarial guard tests.** Keep one deliberately bad sample per recurring failure: chopped word, two intros, one-frame glitch, shaky vertical, off-centre face, unequal marks, crowded figure, unsupported score, and an attempt to publish directly. A guard earns “closed” only when it rejects its bad sample in CI and accepts the good control. Record the test ID and last passing commit in `config/failures.json`; mark mere file/marker checks as configuration coverage.
5. **Independent final review with a stop rule.** Have a reviewer who did not make the cut watch the entire encoded video and read every article visual in context, without seeing the maker's “ready” label. Log defects against exact export hashes. If one high-impact defect is found, the package returns to `review`; only changed assets and their dependent formats are re-approved. Krish should receive a short list of unresolved tradeoffs, not a claim that technical receipts make the package 100% ready.
6. **Make checks an actual merge condition.** During this report's closeout, [PR #151](https://github.com/krishanraja/content-engine/pull/151) merged while its CI jobs were still running, after `gh pr merge --auto --squash`. This proves the current GitHub path did not require those jobs to finish successfully before that merge; the command's `--auto` flag did not provide the intended protection. Configure required status checks and disallow bypass for the release path, then test the rule with a deliberately pending or failing check. Until that is proven, report CI as pending rather than saying a merged PR passed verification.
