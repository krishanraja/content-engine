# ve producing runbook

Target: <1 hour after recording; S0-S8 total **55 engine minutes**, fixes included. Prepare direction/devices before/during recording. Gates/Krish-wait are separate. `ve` means `python scripts/ve.py`; replace <fields>. No --proof/--all flags exist: the proof is its own verb, `ve proof`.

One production round (plan 4 Nov 2026): each decision is made on his own footage before the whole cut renders, one press each on the board's day tab: Sign storyboard (with `ve expect`'s sheet), Pick a style (`ve styles`), Approve proof (`ve proof`), Approve cut (the packet). Never ask in chat what a press asks; an overnight run stops at the next unpressed gate and never renders past it.

stills returns 2 today. Stop unless approved existing stills cover the stage; quick-edit is fallback. This procedure does not certify a complete ve path. In shadow (8 Nov), run S3 to S7 on the same takes as quick-edit and stop before S8: shadow cuts are watched side by side, never filed.

At boundaries: `ve time <piece> status` (0 within 60 min, 1 above), `ve ledger <piece>` (OK/WARN/OVER; 1 above any cap). Log actual usage: `ve ledger <piece> add claude_tokens <n>`, `ve ledger <piece> add codex_tokens <n>`; likewise allowance_points/credits, optionally --note <text>. Finite non-negative amounts only.

At >=80% stop the clock, put an ask in the gate packet and end. Refuse past caps: 60 min, 3.3M Claude, 2.1M Codex, 12.6M total tokens, 1.2 allowance points. Ledger only warns; dispatch checks recorded caps only with --piece; time start checks engine minutes only. Live time appears in time status until stopped. Stop/log before dispatch. Never read big files, individual images or raw logs: use QC JSON and one contact sheet. Human playback/listening still applies. **Maximum 2 fix loops total**: change spec, lint, compile, render, QC; then stop if blocked.

1. **S0; Claude/scripts; 3 min.** In Bash `. scripts/ve-env.sh` pins ffmpeg n8.1.2/tesseract. `ve doctor`: PASS/WARN/INFO, exit 0; hard FAIL exits 1, stop. `ve ledger <piece>`, `ve time <piece> start S0-S1` (started phase, 0), `ve start <piece>` (wrote session-pack.md <=36 KB, 0). Read ENGINE.md, this runbook, pack/spec. start needs an existing spec.

2. **S1; Director/Claude; 5 min.** Two treatments; `ve lint <spec>` after changes (clean, 0). `ve stills <piece>` exits 2: stop unless approved stills exist. `ve expect <spec>` writes `<ve dir>/expect.md`, at most six plain lines of what this cut will and won't do (only the ones that apply: no sfx kit, safe zones listed not held, wide cut with no locked key frames, outside clips muted, numbers said as the script writes them, legacy format, a style with no device); it goes beside the storyboard. Gate 1: Krish signs treatment/stills/bed/credits in storyboard (the Sign storyboard press, bound to the sha256 of the storyboard and expectations he saw). `ve time <piece> stop` prints recorded seconds/totals (0 unless over cap); end at gate. Log actual wait: `ve ledger <piece> add krish_wait_seconds <n>`.

3. **S2; Claude dispatches/verifies, Codex builds; 3 min.** New hero only; otherwise skip. Before/during recording: `ve time <piece> start S2` (0), `ve card <fields.json>` (wrote, 0), `ve time <piece> stop`, ledger check. `ve dispatch <card.md> --piece <piece> --wait` returns companion exit (0 success) where Codex is on this machine; anywhere else (cloud, Claude Desktop, Windows-side Claude Code) it queues the card for Codex on his home computer in WSL (`scripts/velib/codex_lane.py`; push the `.fields.json` to main first) and `ve lane status` shows queued, running, built or failed. The moment a card is queued, start `python scripts/ve.py lane wait <id>` in the background (a Monitor) and act on its first built or failed line; never a timed check-in (F22, Krish 2026-11-02). `ve lane queue` refuses a device card whose verbs are not in EngineEventSchema: add them to `apps/renderer/src/engine/props.ts` first. Never ask Krish to start Codex by hand. The lane needs a Control Center booking (`reserve_credit_spend`, pool codex) passed as `--spend-id`; the building computer reads no credit file. A built card's branch (`ve-card/<card>`) is pushed from the home computer, so WSL needs git access to GitHub once: point Ubuntu's git at the Git Credential Manager that ships with Git for Windows (`git config --global credential.helper` set to its `git-credential-manager.exe` under `/mnt/c/Program Files/Git`). Heartside and Full Time queue their own cards in their repositories (`codex/queue/<id>.md`, config/codex-lanes.json) and the same pass builds them. Log device-work engine_seconds, Codex tokens/allowance; avoid double-counting. Device work shares the cap. Dispatch reserves against the credit caps Control Center places on the publication (`ve budget status`) and refuses over it; a card needing a tool the Codex profile does not allow is held. Runway/Higgsfield/ElevenLabs: `ve ledger <piece> reserve <provider> <amount>` before each generation, `settle` after. The booking itself is Control Center's: the session running the dispatch or generation calls `reserve_credit_spend` before it (refused as over_share, held, unknown or allowance_first: stop), `settle_credit_spend` after with the actual cost and job ids (0 voids it), then `record_credit_balance` (service `codex`, unit `percent`, the percent left; service `codex-credits`, unit `credits`, the paid balance). Without fresh balances Control Center keeps codex-credits shut. The local cap is Control Center's read: monthly runway/higgsfield shares are spread over the weeks before `use_by`. `ve verify-card <card.md> --cwd <worktree>` must exit 0; verifier renders golden stills/reviews one contact sheet. No per-piece code/Codex production edits.

4. **S3; scripts; 6 min.** `ve time <piece> start S3-S5` (0). Per take: `ve ingest <piece> --take <id> --media <file> --aligner-a faster-whisper:small.en --aligner-b <second> [--clock-a <json>] [--clock-b <json>]` (0; two different aligners; the second is another local faster-whisper model; no paid aligner (Krish, 2026-10-29: "do not use eleven labs for this")). Captions are timed by forced alignment, not whisper (Thursday 5 Nov: whisper's word times ran 3 to 19 frames off his voice; MMS and wav2vec2 agreed within 2 frames on all 148 words): write both clocks with `python scripts/velib/forced_align.py <take> <whisper-words.json> mms-fa <a.json>` and `... wav2vec2-960h <b.json>`, then ingest with `--clock-a <a.json> --aligner-a torchaudio:mms-fa --clock-b <b.json> --aligner-b torchaudio:wav2vec2-base-960h`; QC hears the render the same way (`--heard mms=... --heard w2v=... --captions-drawn-by mms`). The signed script words go to `<piece>/ve/script.words.json`. Per cut: `ve conform <piece> --cut <cut> --render --assets-dir <assets> --joins-reel` (0: EDL, words, conformed picture and dialogue from one graph, joins reel; 1: the F09 lint or a line no take read, named). Read its "kept" lines: an unscripted word no agreed gap lets go is for his ear at Gate 3. Premix with `ve premix <spec> --cut <cut> --dialogue <assets>/dialogue.<cut>.wav --words <words> --props <props> --out <assets>/audio.<cut>.wav [--lift FROM-TO per chapter card]` (0; needs `MINDMAKE_MUSIC_ROOT`, which `python scripts/quick-edit/music.py fetch` prints). It writes `audio.<cut>.bed.json` and `audio.<cut>.music.wav` beside the stem for QC. Never retime picture alone.

5. **S4; fresh Director/scripts; 5 min.** `ve start <piece>` rebuilds pack (0); preserve running clock. `ve lint <spec>` must be clean (0). Per cut: `ve compile <spec> --cut <cut> --edl <piece>/ve/edl.<cut>.json --assets-dir <assets>` (after conform; or `--words <words.json>` for an already cut-ready master) prints props hash/path (0); QC then takes the same `--edl` so it measures the conformed joins. compile.<cut>.json needs lint clean, props_sha256, sfx_missing empty. Absent kits report referenced SFX/block status. Unsupported verbs refuse; test_grid draws carry.

6. **S5; scripts/Krish; 7 min. Every piece proves its hardest beat moving (F04, F13).** The style first, after he records: `ve styles <spec> --cut <cut> [--top 3]` takes the top three from `creative_direction.pick_motion` for the spec's points and channel, leaves out (and names) any style whose device is not built, and renders the same 8 to 15 s window once per style to `<ve dir>/styles/<module>.mp4` with `styles.json` (0). No take yet: it uses his last recorded take of the same format, labelled as such, never stock; none at all, it refuses. Until the renderer draws `style.motion` itself the clips can be the same picture (`styles.json` `distinct: false` says so): show them as named styles with their rules. His Pick a style press sets `style.motion` and writes a verdict on all three (`creative_direction.py verdict --module M --verdict picked|seen|not-for-us --said "<his words>" --on <date>`; picked twice becomes tested, not-for-us is never offered again). Then the proof: `ve proof <spec> --cut <cut> [--beat <id>]` (0) renders only the hardest beat (`style.proof.beat` if named; else most distinct devices; ties to a SPLIT beat with a card, then the longest), grown to 8 s and cut to 15 s, from his real take through the same render path, and runs `ve qc` on the clip (`--no-qc` skips). It writes `<ve dir>/proof/<cut>.mp4` and `proof/<cut>.json` (beat, window, sha256, the spec's structural hash, style). `ve time <piece> stop`; end at Gate 2: Krish presses Approve proof or Reject (with his words) on the board. From 9 Nov `ve render` refuses a whole cut until that press is bound to the clip's sha256 and the spec's style, devices and beat plan are unchanged since; a caption edit or a retime under 0.5 s keeps the proof, anything structural needs a new one. Nothing skips proof.

7. **S6; scripts; 14 min.** After acceptance: `ve time <piece> start S6-S7` (0). Each cut: `ve render <props> <cut.mp4> --spec <spec> --assets-dir <assets>` (0, lag/residual/path). Same assets as compile; staged hashes must match. Default scale 1; budget all cuts together.

8. **S7; scripts, fresh Critic/Claude, Krish; 10 min.** Each cut: `ve qc <cut.mp4> --format <format> --props <props> --out <ve-dir>/qc.<cut>.json` (0 measured pass, 1 failure). Require complete; absent OCR is not_run. Use QC JSON/one contact sheet, <=2 fix loops. Before the Critic: `ve refs <piece> <cut>` (0) puts the cut's frames above each inspiration-board reference named in `brand.references` (a reference not on this machine names its Drive id to download). The Critic scores the cut against each card and the scores go to `ve verdict write ... --references <scores.json>`; under 8/10 against any card the cut is NOT READY (`docs/ve/MOTION_STANDARD.md`, F26). From 9 Nov `ve refs` also writes `reference.<cut>.proof.jpg` (the cut above the proof he approved) and the Critic scores it as card `proof`, the same 8/10 rule; no approved proof is itself a hold. `ve packet` opens with "In short", at most ten plain lines (the round, the proof and what changed since, each advisory, each Critic note, the expectations), and counts the round in `<ve dir>/packet.record.json` (a new whole-cut file sent to him is one more; the same file again is not). Critic follows pack card, supplies verdict.<cut>.json. `ve status <piece>` exits 1 until checks/verdicts/exact-file approval exist. A Gate 2 or 3 packet is made only by `ve packet <piece>` (QC, composition, key frames, frozen design lock, and a Critic verdict from `ve verdict write` for that exact file); a new format first needs `ve lock freeze` (`docs/ve/design/TEMPLATE.md`). Log tokens, `ve time <piece> stop`; end at Gate 3 with cuts/joins reel for Krish. Never fabricate passes/approvals.

9. **S8; Claude/scripts; 2 min.** After Gate 3: `ve time <piece> start S8` (0), `ve status <piece>` (every cut READY; it prints `delivered: NO (not filed: run ve file)` and exits 1 until the cut is filed and read back from its 3 Posts folder). `ve file <piece> --subject <post subject> --dry-run` (0, prints where each cut goes), then without `--dry-run` on a home computer with `MINDMAKE_ARCHIVE_ROOT` and `MINDMAKE_LIBRARY_ROOT` set (0; refuses a cut that is not READY, a file changed since approval, or anything already there). It copies each cut into its post's `3 Posts` folder; `ve status` then prints `delivered: DONE <path>` and exits 0 only when that copy reads back (F27). Tell Krish "Done" with the link. Before the cut goes on its making record (`making.py video`, which warns on a cut that leaves out a clip Krish linked to the piece and asked to keep the sound of: `making.py <piece> clips`) or into the library (`send.py`), write its validation receipt: `ve receipt <cut.mp4> --piece <piece> --cut <cut> --piece-id <making id> --library-path '3 Posts/...' --script <signed script> --voice-master <dialogue.wav> [--clarity <dir>]` (0 ready; 1 names what holds it). It hears the cut and the voice master with the same transcriber (Ruling, Krish, 2026-10-31), binds QC, the Critic verdict, his final approval and the words gate to these bytes, and reads his rulings from `<piece>/ve/rulings.<cut>.json` (heard_as, removals, visual_clarity, each in his words). Sync and motion stand as not applicable only when the props hold no picture segments (Ruling, Krish, 2026-10-31). Always `ve time <piece> stop`, even on failure, then `ve ledger <piece>`; retain actual totals. Filing needs an approved route. Never claim unavailable delivery; never publish/send/schedule.
