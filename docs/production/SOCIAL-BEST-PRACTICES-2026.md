# Social Media Creative Production Corpus

**Platforms:** TikTok, Instagram, Facebook, YouTube  
**Scope:** Organic video, photos, carousels, Stories, Reels, Shorts, long-form video, covers, intros, outros, subtitles, interface overlays and QA. Paid-placement differences are noted but this is not an exhaustive ad-policy manual.  
**Research checked:** 12 November 2026  
**Status:** Production reference, not a guarantee that every user/device renders identically.

> **Evidence key:** **[OFFICIAL]** explicitly supported by platform documentation; **[SECONDARY]** current practitioner / industry documentation; **[HOUSE RULE]** conservative production recommendation, not a platform requirement; **[VARIABLE]** depends on app version, account, publishing tool, device, language, UI experiment, caption length or placement. Never convert a house-rule safe zone into a claimed official technical limit.

## 0. The short version: production defaults

1. Shoot/edit mobile fullscreen in **1080 × 1920, 9:16**. Maintain a full-bleed background but keep meaningful text inside a smaller central zone. [OFFICIAL/SECONDARY]
2. Create a **1080 × 1350, 4:5** feed/carousel version for Instagram and Facebook where useful. Create **1080 × 1080, 1:1** only when the layout requires it. [HOUSE RULE]
3. Use **1920 × 1080, 16:9** for conventional YouTube long-form. [OFFICIAL]
4. For a cross-platform 9:16 master, start with the **conservative core rectangle x=120–820, y=330–1180** on a 1080×1920 canvas. Place critical subtitles, hooks, CTA text, logos and data in this region. It is a **HOUSE RULE**, deliberately narrower than the visible screen and not an official guarantee for every TikTok UI. Verify actual preview before publishing.
5. **No logo-only cold open** for short-form. Start with the story, an identifiable image, or a value proposition in frame 1. Brand within the action. [HOUSE RULE; aligned with TikTok guidance]
6. Use a compact native-looking end beat rather than a 4-second dead outro. For YouTube long-form, reserve 5–20 seconds for actual clickable end-screen elements. [OFFICIAL for YouTube end screens]
7. For spoken content, provide accurately timed captions; don't bake two overlapping caption systems into the same frame. Keep closed captions or platform auto-caption rendering in mind. [HOUSE RULE]
8. **Always test** the uploaded preview with UI visible, captions expanded/collapsed, on a small phone and a tall phone where feasible. [HOUSE RULE]

## 1. Format and aspect-ratio vocabulary

| Ratio | Standard working canvas | Best use | Main risk |
|---|---:|---|---|
| **9:16** | **1080×1920** | TikTok videos and photo mode, IG/FB Reels and Stories, YouTube Shorts | Top/bottom/right action chrome covers video |
| **4:5** | **1080×1350** | IG/FB vertical feed photos, feed carousels, feed graphic/video variants | May be cropped differently in profile grid or Reels viewer |
| **3:4** | **1080×1440** | Portrait Instagram photo uploads where supported; 3:4-oriented profile-preview workflows | Support and crop behavior can differ by format and scheduler |
| **1:1** | **1080×1080** | Square feed graphics and carousels, YouTube community images | Less screen real estate; square ≤3-min uploads may classify as Shorts on YouTube |
| **16:9** | **1920×1080** | YouTube full videos, landscape Facebook feed videos | Tiny inside a vertical feed; letterboxing or alternate display |
| **1.91:1** | **1080×566** | Horizontal feed photos / some ad placements | Shallow on mobile; weak for text |
| **16:9 thumbnail** | **1280×720** or higher 16:9 | YouTube long-form thumbnails | Overlayed duration/time badges on some surfaces |
| **9:16 thumbnail** | **1080×1920** working canvas | Shorts / Reels / TikTok cover art | Profile grid crops vertically and horizontally |

**Resolution vs ratio:** 1440×2560 and 1080×1920 are both 9:16. Higher resolution does not create a bigger safe area; margins scale in percentage terms. Upload limitations differ by publishing route. Avoid treating a scheduler's constraints as platform limits.

## 3. Anatomy of a 9:16 screen: what covers what

Draw your creative on a pixel canvas with origin `(0,0)` at top-left, `x` increasing rightward and `y` downward. All below are based on **1080×1920**.

### 3.1 Common UI hazards

| Zone | Typical elements | Creative risk |
|---|---|---|
| Top strip | For You/Following or Reels header, search, account, back controls, story progress | Titles / logos chopped or visually crowded |
| Right edge | Profile/follow, like, comment, share, bookmark, remix, product link | Captions and faces hidden behind floating controls |
| Bottom-left | Handle, caption/description, hashtags, audio name, location/creator attribution | Subtitle or CTA collides with multiline text |
| Bottom centre | Playback / seek, reply field, product or CTA tray | Closing line and subtitles disappear |
| Bottom-right | Actions and audio-disc icon, subscribe or Remix | Repeated collisions with logos, price chips |
| Expanded description | Multiline text, hashtags, tags | Dynamic safe-zone shrink; a collapsed-caption test is insufficient |
| Viewer-dependent | Translate, shop link, branded-content labels, live indicator, subtitles, sticker, polls | UI moves based on placement and locale |
| Profile/grid/list | A **crop of the cover**, often not the full Reel frame | Headline/face vanishes even though fullscreen playback looks good |

### 3.2 Meta Reels ad guardrail vs organic viewing

A frequently published **Meta Reels ads** guardrail is approximately **top 14%, bottom 35%, 6% left and right**, equivalent to:

- Top: `y < 269` px
- Bottom: `y > 1248` px
- Left/right: `x < 65` or `x > 1015` px
- Resulting central ad-safe rectangle: `x=65–1015, y=269–1248`

**Important:** This is an **ads placement guide**, not a Meta guarantee that organic Reels' right-side controls will never overlap inside that rectangle. The action stack may justify a much larger right-side buffer. For disclaimers on Meta Reels ads, plan up to **40% bottom clearance** where that rule applies. [SECONDARY referencing Meta Ads Guide; validate in current Meta Ads Manager.]

### 3.3 TikTok

TikTok explicitly says the safe zone **depends on format, caption length and interactive add-ons**. It provides downloadable ad-safe templates and previews instead of one fixed universal organic pixel coordinate. Longer captions reduce safe space. [OFFICIAL]

- Right-side action column: never put subtitles, product prices, logos or fine details underneath it.
- Bottom-left metadata: leave substantial clear space below subtitles.
- Top navigation: don't put first-frame title flush to the top edge.
- Multi-line caption, ad anchor, paid CTA or interactive add-on: retest, do not reuse a simplified overlay unquestioned.
- Right-to-left variants: TikTok has distinct ad templates. [OFFICIAL]

### 3.4 YouTube Shorts

YouTube Shorts' right action column and bottom attribution/description produce similar but not identical occlusions to TikTok or Reels. A current industry synthesis of Google's **video ads** template reports a vertical safe area approximately `x=48–888, y=288–1248` for a 1080×1920 ad; this is **not a verified official organic Shorts UI boundary**. [SECONDARY]

Design with a larger inset for subtitles than the technical video edges, and test Shorts app playback with the control strip visible.

### 3.5 Recommended cross-platform safe regions [HOUSE RULE]

For 1080×1920:

| Layer | Proposed box / range | Why |
|---|---|---|
| Full-bleed visual | `x=0–1080, y=0–1920` | Backgrounds fill screen; crop allowed |
| **Critical content master** | **`x=120–820, y=330–1180`** | Conservative combined inset for action stack and top/bottom chrome |
| Primary opening hook | `x=140–820, y=360–720` | Seen early, away from top tabs and right buttons |
| Subtitle area | **`x=130–820, y=940–1160`** | Above bottom metadata, clear of right actions; ~2 lines |
| Logo / small credit | `x=140–780, y=360–940` if essential | Avoid watermark-like right-bottom placement |
| Last CTA | `x=140–820, y=820–1150` | Brief and legible, not below the platform CTA |

This master box is intentionally **more restrictive** than Meta's cited ad template. The best usable region on one platform may be larger; platform-specific renders can take advantage of that. **Any dynamic captions, translated overlays, product stickers, unusually long descriptions or very tall phone can still invalidate it.** A safe rectangle is a starting geometry, not a substitute for a real preview.

### 3.6 Quick aspect-ratio math

- 9:16 canvas: `W=1080`, `H=1920`
- Protected margins as percentage: `margin_px = fraction × relevant_dimension`
- Resize any coordinate from 1080×1920 to another 9:16 resolution via `x_new = x × new_W/1080` and `y_new = y × new_H/1920`.
- Use the **rendered placement** for QA. Pixel overlays measured in a video editor do not perfectly predict UI scaled by a phone's physical screen.

## 4. Intros and opening cards

**Goal:** establish instantly what the viewer will get, not announce that a brand exists.

### 4.1 Short-form (TikTok, Reels, Shorts)

- **Frame 1:** include a human, compelling object, event, contrast, question or proof, not an empty branded slate. [HOUSE RULE]
- **First 1–3 seconds:** place the hook inside protected upper-middle area; don't require reading a paragraph. TikTok's own guide emphasizes the first 3 seconds and discourages long logo intros. [OFFICIAL]
- **Card duration:** a 0.5–1.5-second title beat often works better than a separate 3–5-second splash. Use as an editorial choice, not algorithmic guarantee. [HOUSE RULE]
- **Type:** one claim or question, usually no more than 6–12 visible words if the visual is busy. Better still, 3–7 words. [HOUSE RULE]
- **Visual continuity:** don't switch from a stark intro frame to unrelated footage unless the contrast is the storytelling device.
- **Audio continuity:** spoken line and visual hook should reinforce rather than duplicate unrelated points.
- **Identity:** brand mark subtle, usually embedded in opening visual or lower-risk mid-frame; avoid imported TikTok/Reels watermarks on cross-posts.
- **Accessibility:** do not rely on audio alone; give an equivalent visible hook.

### 4.2 Instagram / Facebook carousel first slide

- First card functions as a thumbnail and a mini headline, not a video title animation.
- Use **4:5 1080×1350** as the default feed carousel variant; keep all carousel frames consistent in size.
- Reserve generous 60–100px *design* margin (house rule; not fixed app UI exclusion).
- Lead with a useful promise, strong result, surprising data point, or recognizable problem; avoid “Swipe to learn more” as the only value proposition.
- Show swipe affordance lightly if helpful: tiny `1/6`, a teaser at edge, or an intentional continuation. Don't fake native arrows/buttons.
- First and second slides must each be comprehensible when isolated or screenshotted.
- Treat a mixed video/photo carousel as a coherent series with shared typography, brightness and baseline.

### 4.3 YouTube long-form intros

- **Thumbnail and title set the expectation** before play; don't waste first 5–15 seconds reading them again.
- Start with the claim, result, demonstration or tension; a brief animated logo may follow, not precede, value.
- For tutorials, show outcome and specify what will be explained; for essays, state the analytical question; for interviews, use the strongest evidence-backed moment.
- Avoid “subscribe first” requests before value is demonstrated.

## 5. Outros, final cards and end screens

| Format | Suggested finish | Avoid |
|---|---|---|
| TikTok / IG Reels / FB Reels / YouTube Shorts | **One-line final payoff + one next action** embedded over continuing footage, often 0.5–2s [HOUSE RULE] | Long silent logo, tiny QR code or links, native fake follow button |
| Instagram / Facebook carousel | Final slide with a **self-contained takeaway**, then a small optional CTA | Empty “thanks for swiping” slide, 4 different actions |
| Story sequence | CTA matching available native affordance: reply, poll, link sticker or next story | Placement of fake UI over real reply/CTA area |
| YouTube standard video | Reserve **last 5–20 seconds** for clickable end-screen templates; minimum video length **25 seconds** [OFFICIAL] | Burned-in “click here” where no clickable element actually appears |
| YouTube live replay | Outro plus appropriate real card/links/chapters when supported | CTA obscured by player end controls |

**YouTube end-screen rules [OFFICIAL]:** Standard 16:9 videos may include up to four clickable end-screen elements; time window is last 5–20 seconds, and videos must be at least 25 seconds long. Place visual placeholders where the selected YouTube Studio end-screen elements will actually be located. Use YouTube Studio preview, and note end screens don't display in all contexts and viewers can hide them.

**Outro production tests:** Does the last spoken line land before the viewer swipes away? Is the CTA achievable **on that surface**? Is the on-screen instruction still true if a native clickable overlay is absent? Is the final frame an attractive paused frame/loop boundary?

## 6. Captions: distinguish three different objects

1. **Post caption / description:** text entered during upload. Appears in platform UI, often truncated, sometimes under the video. Changes the safe area when expanded.
2. **Open captions / burned-in subtitles:** visibly rendered into video pixels, cannot be switched off. Full control of timing and brand; risk of duplicate captions and UI collision.
3. **Closed captions / platform captions:** separate text track, automatic speech recognition or uploaded caption file, potentially user-toggleable, translated, style- or placement-dependent.

### 6.1 Burned-in subtitle design [HOUSE RULE]

- Use **accurate verbatim or carefully edited readable speech**, with no invented words.
- For fast mobile content: **1–2 lines** and usually **3–7 words per timed segment**, adjusted to delivery speed. Avoid a full paragraph.
- Put baseline in the **central-lower protected region**, not the bottom “lower third” of a video: for universal 1080×1920 use around **y=940–1160**.
- Keep every subtitle **left of x≈820** in the universal master to avoid right-side icons.
- Use strong contrast: light letters with a dark outline/shadow or restrained opaque backing. Check over moving footage.
- Approximate working font size for 1080-wide shorts: **44–64 px**, subject to font metrics, accessibility and copy length. Not a platform mandate.
- Avoid excessive all-caps, dense bounce/karaoke per-word effects, decorative emoji substitutions and word-by-word flashing if they reduce reading accuracy.
- Break at meaningful phrases, don't orphan single short words without a reason.
- Caption speech sounds and relevant non-speech meaning where accessibility requires it. Mark speakers when unclear.
- Avoid subtitle collisions with *other creative* text: hooks and captions need separate time positions or dynamic layout.
- Prefer explicit SRT/VTT caption tracks where a platform and publishing workflow reliably support them; preserve a clean master.
- Native automatic captions may appear in different places and can be inaccurate: always review their transcript and render.

### 6.2 Post descriptions

- First sentence is the opening text likely to be visible before “more”. Put a clear proposition there.
- Use platform-specific text: TikTok conversational/searchable, IG useful hook + a little context, Facebook self-contained/contextual, YouTube searchable title + detailed description/chapters for long-form.
- Hashtags should be **relevant, sparse and descriptive**, not a wall of reach-bait. Platform limits/recommendations change.
- Avoid URLs that are not clickable in that particular surface. “Link in bio” only when a functional bio link exists; Story link sticker when available; YouTube description links where supported.
- Hashtags, mentions, hashtags in title and platform labels can change rendered line count. Test with the **actual planned description**.
- For subtitles, do **not** assume a shorter post caption makes all of the platform UI disappear.

### 6.3 Platform caption traps

| Surface | Trap | Fix |
|---|---|---|
| TikTok video | Long description can reduce safe zone; soundtrack label at bottom | Preview with actual description and sound selected |
| Instagram Reel | On-video captions + IG auto captions duplicate; first profile crop hides title | Choose one visible caption strategy; test Reel viewer and grid cover |
| IG/FB Story | Reply field, link sticker or poll blocks low content | Keep meaningful text mid-screen; position stickers only after checking UI |
| Facebook Reel | UI layout differs in full-screen and feed preview | Review mobile feed + full-screen Reel |
| YouTube Short | Shorts UI and automatic subtitles can overlay your design | Verify on phone with captions on and off |
| YouTube long-form | Player controls cover bottom edge when active; captions may sit at bottom | Place persistent lower-thirds above controls or leave shiftable captions |

## 7. Covers, grid crops and thumbnails

### Instagram Reel cover

- Design/export cover in **1080×1920** if using fullscreen creative.
- Assume the profile grid presents a cropped preview rather than an entire 9:16 image; current examples commonly use a **3:4-style grid preview**, but the crop may vary by interface and account.
- Place cover-critical **face, headline and brand** in an additional **central 3:4 crop** (approximately y=240–1680 if centred in a 1080×1920 cover). This 3:4 crop is a design preview model, not a guarantee of actual crop coordinates.
- **Crucial conflict:** a headline safe in the middle 3:4 grid may lie under fullscreen viewer controls. If a single frame cannot satisfy both, export **a separate Reel cover** and **a separate in-video opening frame**. Never force one design to do both.

### TikTok cover

- Choose a recognizable, readable frame; inspect TikTok profile-grid crop rather than assuming 9:16 display.
- Ensure title can survive truncation and a square-ish centre crop. Use a separate cover treatment when editor supports it.

### YouTube Shorts cover

- YouTube's current desktop Studio documentation permits custom Shorts thumbnail upload for verified channels; recommends 9:16. This workflow has changed over time, so confirm for the actual account/client. [OFFICIAL]
- Use a recognisable subject and short oversized headline. Check Shorts shelf and channel tab crop.

### YouTube long-form thumbnail

- Create at least **1280×720**, ideally higher-res 16:9 source if needed. YouTube now recommends as large as **3840×2160** for standard thumbnails. [OFFICIAL]
- Design for a small mobile presentation: one unmistakable subject, high contrast, minimal text, strong face/object separation.
- Avoid lower-right text; video duration pill often appears there. Avoid small logos.
- Title and thumbnail should complement rather than duplicate all the same words.

## 8. Static image and carousel production system

### Standard carousel template [HOUSE RULE]

- Default 1080×1350 portrait Instagram/Facebook feed slides; 1080×1920 vertical TikTok image slides.
- Keep shared component tokens: typographic scale, padding, progress indicator, visual motif.
- Slide 1: the result/question, not an overt branded title page.
- Slides 2–N−1: one idea / proof / comparison per slide. Preserve scan speed and rhythm.
- Final slide: synthesis plus one sensible CTA. A save-worthy summary often beats a sell-heavy card.
- Keep a protected text inset of **70–100 px** for 1080-wide feed assets as a *design margin*, not because Instagram has a button column superimposed over every carousel slide.
- Don't rely on adjacent slides to complete the meaning of a sentence unless intentional and immediately legible.
- Maintain alternative text, adequate contrast, accessible chart legends, and source attribution on data-heavy slides.
- If posting as a video carousel or a Reel made from slides, reapply the **video UI safe zones**, not just the feed-carousel margins.

### Operational distinctions

- **Instagram carousel:** current industry documentation gives up to 20 items in the native flow; confirm the scheduler's own limit. Carousel items may include videos; choose consistent ratio and style. [SECONDARY]
- **TikTok organic photo post:** differs from paid TikTok Carousel Ads; vertical works well and music/controls are part of consumption. [SECONDARY]
- **TikTok Carousel Ads:** September 2026 specs distinguish standard image carousel (2–35 images) from VSA carousel (2–20). Music and caption/CTA rules are ad-specific. [OFFICIAL]
- **Facebook multi-photo posts vs Carousel Ads:** do not assume every organic photo album is a swipe-based linked carousel.
- **YouTube Community posts:** image sequences aren't timed Shorts and lack video subtitle treatment.

## 9. Platform-specific design notes

### 9.1 TikTok

**Formats:** organic feed video, photo mode, livestream/live clip, duet/stitch/remix-derived video, Spark/non-Spark ads, image carousel ads. Different modes introduce different labels and overlays.

- Default 1080×1920, 9:16, full-bleed. [OFFICIAL]
- Hook at frame 1, clear value within first ~3 seconds; minimal branded intros. [OFFICIAL]
- Right action stack and lower metadata are major occlusion zones. [VARIABLE]
- Long post captions and interactive add-ons alter ad safe-zone geometry. [OFFICIAL]
- Ad specs aren't interchangeable with organic duration/size limits; e.g. Non-Spark in-feed ads specify up to 10 minutes while organic uploads may have other limits. [OFFICIAL/VARIABLE]
- TikTok image ads guidance recommends 9:16 images, high-resolution images and text inside safe zones; its **3 or 7–9 slide** suggestion is an ad testing observation, not an organic algorithm rule. [OFFICIAL]
- Use a cover frame with a high-contrast focal subject, separately QA profile preview.

### 9.2 Instagram

**Formats:** single-image feed, single-video/Reel, mixed/photo/video carousel, Stories, Reels, Collab posts, live/video recording, ads.

- Reels/Stories 1080×1920 master; feed carousel typically 1080×1350 or 1080×1080. [SECONDARY]
- Reels action strip right, captions/audio/identity bottom; Stories progress/header top and reply area bottom. [VARIABLE]
- Reels' 9:16 full-screen and profile grid crop are **different deliverables** when a cover headline must be perfectly framed.
- Keep carousel text away from crop boundaries; use a consistent aspect ratio.
- Avoid stacking big on-video text and auto-captions. For talking-head content, leave room below the chin and above the UI.
- Consider whether a single-video feed upload becomes a Reel under the current interface rather than relying on historical categories.
- Longer Reels can be uploaded in some routes; don't confuse upload maximum with optimal reach or eligibility. Verify before declaring a strict limit.

### 9.3 Facebook

**Formats:** Reels, Stories, video posts (increasingly integrated into Reels), feed photos, multi-image posts/albums, live, video/carousel ads.

- Use a 9:16 mobile Reel master and a 4:5/square feed image when this serves the target placement.
- Facebook Page feeds, personal profiles and Reels viewers can compose content differently; test the actual publication target.
- Captions may be particularly important for sound-off feed playback. Ensure subtitles don't obscure the main object.
- Cross-posting from Instagram does not guarantee identical cover crop, descriptions, interactions or link behavior.
- Facebook organic photo posts and paid carousel ads are **not** the same format.

### 9.4 YouTube

**Formats:** Shorts, conventional long-form, livestreams and replays, Premieres, Community image posts, in-stream/in-feed/Shorts ads.

- **Shorts:** eligible square or vertical video up to **3 minutes** is categorized as a Short under YouTube's documented rules for uploads from October 15, 2024 onward (with artist channel exceptions). [OFFICIAL]
- **Long-form:** standard desktop player is **16:9**; player adapts for other ratios. [OFFICIAL]
- **End screens:** **5–20 seconds** at end, only for videos **≥25 seconds**; up to four elements on standard 16:9. [OFFICIAL]
- **Thumbnail:** standard 16:9 with large readable subject; Shorts 9:16. Current desktop Studio custom Shorts thumbnail support should be verified in the channel. [OFFICIAL]
- **Export:** MP4/H.264/AAC, frame rate consistent with source; 1080p SDR 8 Mbps at 24–30 fps or 12 Mbps at 48–60 fps per YouTube recommendations. [OFFICIAL]
- **Subtitles:** prefer a reviewed closed-caption track and avoid persistent lower-third graphics that make captions unreadable when player controls are active.

## 10. Technical export preset

**Cross-platform mobile video / “vertical master” [HOUSE RULE, compatible with common official recommendations]:**

```yaml
profile: vertical_social_1080p
width: 1080
height: 1920
aspect_ratio: "9:16"
container: mp4
video_codec: h264
pixel_format: yuv420p
frame_rate: preserve_source_or_30fps
scan: progressive
color: bt709_sdr
video_bitrate: "8-12 Mbps working default; platform recompresses"
audio_codec: aac
sample_rate: 48000
channels: stereo
true_peak: "avoid clipping; set loudness to platform-appropriate program material"
subtitles:
  clean_master: true
  optional_burned_in_variant: true
  reviewed_srt_or_vtt: true
critical_content_box_1080x1920:
  x_min: 120
  x_max: 820
  y_min: 330
  y_max: 1180
  status: "house-rule; test live preview"
```

**YouTube long-form master:** 1920×1080, 16:9, MP4/H.264/AAC with source frame rate; 4K when source/output needs it. YouTube's 1080p recommended bitrate is **8 Mbps** for standard fps and **12 Mbps** for high fps. [OFFICIAL]

**Static masters:** PNG for text/graphics with flat colours; high-quality JPG for photos; validate final file size and format in actual publishing workflow. Don't use low-res thumbnails as upload masters.

**Audio:** voice clarity first; music under speech, avoid clipping, test phone speaker and headphone, confirm rights by platform and commercial account. A music licence on one platform does not automatically authorize another.

## 11. Automated QA acceptance checklist

### Geometry and overlays

- [ ] Detect format correctly (`9:16`, `4:5`, `3:4`, `1:1`, `16:9`); no unintentional crop/stretch or bars.
- [ ] For 1080×1920, critical text/face/CTA avoid the **house-rule x=120–820, y=330–1180** outside region, unless a platform-specific preview explicitly validates the exception.
- [ ] No subtitle intersects simulated right-hand like/comment/share stack.
- [ ] No important text disappears behind bottom caption, progress bar, CTA, reply field, or top navigation.
- [ ] Test **collapsed AND expanded post description**, selected audio, translated text if relevant, and any paid/shop sticker.
- [ ] Test on small and tall phones; account for app version/OS differences.
- [ ] Profile grid/cover, feed preview, full-screen view, story view are separately checked where applicable.

### Content quality

- [ ] First visible frame conveys subject/story, not a dead logo bumper.
- [ ] First spoken and visible hook align; no unnecessary delay.
- [ ] Intro/outro card duration is justified, no long branded dead air.
- [ ] One clear value proposition and one appropriate next action.
- [ ] Sources and statistics validated; commercial disclosures and music rights checked.

### Captions and accessibility

- [ ] Transcript accuracy manually reviewed; no obvious omissions.
- [ ] Timecode, reading speed, line breaks and speaker clarity checked.
- [ ] High contrast on most difficult actual frame, not only on white/black test background.
- [ ] No duplicated burned-in and native captions on default experience.
- [ ] No seizure-risk flashing or excessive high-frequency text animation.
- [ ] Alt text for images; audio not only carrier of meaning; visual not only carrier of vital instructions.

### Rendering and publishing

- [ ] MP4 plays and decodes; colour, sound and sync checked.
- [ ] Caption track correctly imported or the open-caption variant chosen intentionally.
- [ ] Cover/thumbnail survives platform crop and tiny mobile view.
- [ ] Correct native export for each placement, not an unexamined cross-post.
- [ ] Current platform upload constraints checked before publish; account-specific scheduler limitations documented separately.
- [ ] Final **native app preview** visually inspected before approval/publication. Automated static tests do not prove app UI success.

**Implementation design:**

1. Keep **source video**, **clean exported master**, **burned-in subtitle variant**, **caption sidecar**, **cover image**, and **platform-specific metadata** as separate artefacts.
2. Build platform/placement overlays with a **source and review date**, not a single immutable generic safe-zone mask.
3. Maintain **minimum critical-content box** and optional larger platform-specific boxes. Encode as named presets, not magic numbers scattered through the editor.
4. Use OCR/computer-vision solely for *automated QA of generated assets* if reliable; don't mark live UI clearance “verified” without screenshot comparison.
5. Persist a test evidence screenshot or manually validated render for each distinct UI placement.
6. Version the presets. Trigger review when a platform changes its app chrome, ratio or thumbnail workflow, or after a verified overlap failure.
7. Separate **creative recommendation** (house rule) from **publishing validation** (actual platform limits).
8. Publishing, paid spend and scheduling should remain explicit approval-gated operations.

## 13. Failure patterns worth catching automatically

| Failure | Typical cause | Guardrail |
|---|---|---|
| Captions under like button | Subtitles centred across full 1080px width | Max subtitle right edge x≈820 in shared master; verify in app |
| Captions behind username/music | Subtitle baseline near bottom | Move to y≈940–1160; preview metadata expansion |
| Logo under Story reply bar | Reusing Reel outro unchanged for Story | Story-specific visual QA / reflow |
| Grid headline cut off | Fullscreen 9:16 used as grid cover | Separate cover with profile crop preview |
| Platform auto captions duplicate burned text | Upload auto-caption default enabled | Review native captions and choose one system |
| TikTok CTA blocked on ad | Paid anchor/long ad caption changed safe zone | Ad preview with final metadata/add-ons |
| Flat first 3 seconds | Standalone intro logo animation | In-scene hook, move logo later |
| YouTube end-card CTA not clickable | Rendered fake visual buttons, not Studio elements | Map to actual end-screen elements |
| Carousel second slide clipped | Mixing aspect ratios / first-item enforced crop | Lock slide ratio and export consistent files |
| White subtitle unreadable | Bright footage or nonuniform outline | Contrast-backplate / stroke and hardest-frame QA |
| Wrong claims about “max duration” | Confusing platform upload, scheduling tool and ad limits | Store limit with platform, route, placement and check date |

## 14. Maintenance and confidence notes

- This corpus is dated **12 November 2026**; platform UI can change without public documentation.
- **High-confidence primary-sourced:** YouTube Shorts 3-minute categorisation; YouTube end screens; YouTube standard export; TikTok video ad ratio and dynamic safe-zone statement; TikTok standard carousel ad specifications.
- **Medium-confidence / externally documented:** Instagram 20-item carousel, 3:4 grid tendencies, current organic maximum Reel duration and Meta ads safe-zone percentage summaries.
- **House-rule, unvalidated against every device:** the proposed universal critical-content rectangle, hook timing, type size, subtitle line count, recommended card duration, and exact mobile UI hazard envelopes.
