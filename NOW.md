# Mindmake Video and Carousel Studio: where it is right now

## What it is

Mindmake Video and Carousel Studio is the governed production engine behind Mindmake's publication: it turns an approved editorial brief into deterministic Shorts and swipe carousels for The Money of AI and Built With AI, and nothing renders, packages or uploads until Krish has approved the exact artifact hash. It is a TypeScript and Remotion studio with a hash-locked Python transcription runtime, a Windows Scheduled Task runner that executes Control Center commands without any chat session, and a carousel director that shares the video engine's evidence, approval and learning rules while using its own story, slide and render contracts. Since 2026-09-08 (PR #42) this repository also holds the Content Engine control plane: the editorial capture, brief, judge, radar, AEO and purge routes that used to live in `krishanraja/control-center`, moved here so that "the whole Content Engine is one repository to develop in" (`apps/control-plane/README.md`) and now deployed as its own Vercel project reached through Control Center's rewrites. Codex, Claude Code, Claude.ai, ChatGPT and Control Center are windows into the studio side of the engine (`docs/ENGINE_SESSION.md`); a repository checkout gives instructions, not production authority. The studio optimises honest reach, retention, sharing and qualified action. It never publishes publicly: YouTube upload is private-only, and LinkedIn, TikTok and Instagram output stay local packages for a human to post (`AGENTS.md`). In the Content Engine registry this repo is `video-studio`, "the bespoke AI video production agency: a governed render engine, carousel engine and review surface"; that registry entry predates the control-plane move and has not yet been re-scoped to say so.

## Who it is for and why it matters for Mindmake

The studio is not sold. It is the production system behind what Mindmake does sell and publish, and it is a proof asset. The room_face buyer (`control-center/docs/ICP.md`: a senior leader at a PE or VC backed media, adtech, publishing or data business, quietly behind on what is coming and unable to say so inside their organisation) runs a media business and is watching one person build a governed, deterministic production pipeline in which every taste rule needs explicit approval. What this repo proves is that AI production can be governed rather than merely generated: the machine proposes, the record shows why, and a person decides against an exact hash.

Stories a writer can carry without asking Krish:

- **A rule becomes taste only when a person says so.** Feedback moves through `observed`, `inferred`, `confirmed`, `trial`, `eligible`, `user_approved`, `active`. A rule is active only after the exact rule appears in reviewed Git configuration, and views alone can never make one eligible (`docs/ARCHITECTURE.md`, "Learning boundary"). Codex and system diagnostics are observations and cannot become taste rules.
- **A panel of judges never decides; it only predicts, and its own predictions are graded.** Six idea judges and seven draft judges each answer one question, blinded, in parallel, and disagreement is preserved rather than averaged; the prosecutor argues for killing a piece and can never set the winning score. `judge_calibration` then asks whether a judge's verdict predicted what Krish actually did, so a judge that never changes an outcome can be proposed for retirement (PR #43).
- **The first rendered carousel was rejected, and the record says why.** Repeated dark backgrounds, generic boxes, inert space and duplicate series labelling failed the standard "even though deterministic tests passed" (`docs/CAROUSEL_ENGINE_STATE.md`, "Appendix A: Decisions"). Three replacement concepts went to two blinded judges; the approval-interlock spine won 72.0 and 71.5 out of 80 (`docs/CAROUSEL_ENGINE_STATE.md`, "Appendix C: Reset trace").
- **Fail closed beats shrink to fit.** Every branded render must show the official wordmark's real lettering at 50 render pixels or more; if no collision-free placement exists, rendering and QA fail rather than covering Krish or shrinking the mark (`README.md`).
- **The machine keeps evidence, not transcripts.** The session contract records tool-backed actions, exact feedback excerpts and artifact differences, and never a whole chat transcript. Silence is not feedback (`docs/ENGINE_SESSION.md`).
- **A wrong diagnosis gets corrected in the open, not quietly dropped.** A commit that blamed a production failure on a lost run was followed a day later by one titled "Correct the record: no run was ever lost", which named the mistake ("I queried the ledger while the insert was still in flight and read absence as loss") and kept the underlying fix (PR #50, PR #51).
- **Nothing publishes itself.** A merged code change is not an installed runner, and an installed runner is not a live integration until seven named steps succeed (`docs/DEPLOYMENT.md`).

Objection it answers: "AI content is slop." Here is a pipeline that refuses to make the video when the source cannot clear the bar, and writes down the refusal.

## Where it is right now (as of 2026-09-09)

Lifecycle: building. Nothing in the repo records a live render, an installed runner, a published carousel or a public upload. Every claim below points at a file at `733121f` unless a different sha is named.

- **Content Engine control plane.** Moved into this repo from `krishanraja/control-center` and now deploys as its own Vercel project (PR #42, `a20e442`). It holds the editorial spine (capture, Composer, weekly brief, shifts, the Monday purge), the supply side (feed, AEO, creator scout, lens radar, investigations), and `api/video-studio/**` (the Studio's own operator reads, magic-edit commands and runner protocol, unchanged in URL because Control Center reaches everything through rewrites). `api/content-engine/health.ts` reports what is scheduled, when each job last ran and whether the operator guard is configured (`apps/control-plane/README.md`).
- **Beat gate.** Written 2026-08-06 but only wired into the radar, investigations and creator posts; `feed/ingest` and `shifts/detect`, the two routes that actually build the corpus, never called it, so a classifier downstream discarded 28 of 47 live arcs by hand (60 percent, on the line the code's own `DISCARD_ALARM` message calls a corpus fault, not an ontology one). Both routes now call the gate. A new `NEVER_BEAT` tier refuses safety and security stories outright, above the economic-rescue tier, after 18 of 113 live rows that had passed were exactly that; `ON_BEAT` price matching is now prefix-tolerant after it missed "repriced" (PR #64). The gate now passes 75 percent of the corpus and leaks none of the excluded categories.
- **Editorial radar.** Had never returned a usable verdict: a single model call asked for roughly 20 opportunities inside a token budget that left no room for an answer, every response truncated mid-JSON, and the fallback silently wrote a fabricated `no_angle` rejection that then cached for 20 hours per headline, permanently, because a headline's source hash never changes. All 40 judged ideas carried the identical fabricated reason before the fix. A signal the lens did not answer for is now recorded as `unjudged` and retried rather than cached as a verdict, and calls are chunked to 5 signals so a batch failure costs only itself (PR #63). The same commit stops every AEO recommendation being judged as editorial content by default; a subject earns the `publication` lane only via an explicit `EDITORIAL_AEO_SUBJECTS` allowlist, which ships empty.
- **Runner and control-plane wire contract.** The runner validated requests with zod while the control plane parsed them by hand in 139 lines with no test that the two agreed. An equivalence harness proved the shared schema first and found one real gap: preview upload's `lease_token` was bounded below but not above in the old parser (Phase 3, PR #61).
- **Judge panel, edit ledger and purge.** Landed together because the ledger is what makes the panel accountable: `judge_calibration` joins verdicts to what Krish actually did, keyed by `panel_run_id`. The Monday purge, the engine's only hard delete, now copies every row to private Storage before deleting it and refuses to delete at all if the export fails; restore is additive and idempotent by original id (PR #43).
- **Screenshot lane and creator moves.** A Drive-dropped screenshot now identifies the post by the URL read out of the image (or a content hash) instead of the Drive link, so the same post from two devices collapses to one idea. `creator_moves` records the transferable move a curated creator's post teaches, keyed by a hash of normalised post text so a scrape and a screenshot of the same post collapse too, and `_creatorFingerprint.ts` refuses a draft that shares a run of more than eight consecutive non-grammar words with its source (PR #45).
- **AEO research lane.** Ported in ahead of a `control-center` PR that would otherwise have deleted it outright; the merge conflict was "the useful kind" (PR #47).
- **Video engine (V2 visual story director).** Built and merged 2026-09-04 (PR #23); the runner, brand gates and Drive discovery followed (PRs #24 to #35). Approvals on record: the compact stacked wordmark lockup (PR #22, theme `mindmake-video-v1` version 3) and the `evidence-kinetic-ribbon-v1` treatment for Built With AI solo work, which still needs a per-job layout review (`README.md`). Short-native work requires an exact approved `ProductionBriefV1` from Control Center (PR #38), and the installed runner can claim that brief itself (PR #39, `docs/OPERATIONS.md`, "Control Center production intake"). The four-week pilot in `docs/PILOT.md` has no recorded start, and no Short has a recorded final approval, package or upload.
- **Carousel engine.** State: `docs/CAROUSEL_ENGINE_STATE.md`. Product method locked by Krish 2026-09-07 and encoded in `config/carousel-visual-direction.json`. Since PR #44 (2026-09-08) the confirmed anti-slop editorial standard (no sensational framing, no follow or comment bait, an early proof or artifact beat) is enforced in code for both series through a `source_format` shared with every other canonical format, not just carousels. Current rendered candidate `built-approval-interlock-v2`; the revised brand placement (series wordmark top-left, Mindmake bottom-left) is still provisional until Krish approves the rendered review set. Production rendering needs exact story and visual-direction approvals; packaging needs exact final approval; neither is recorded.
- **Windows runner and control plane.** Runner daemon, Scheduled Task installer, Drive Inbox discovery and Control Center command client are merged. A rotation script for the runner's signing key now exists (dry run by default, refuses to run on a signature missing its hash or one that fails to verify under the current key), and a `/api/content-engine/runs/replay` route can replay a single failed job while refusing the two that delete or cost money (PRs #55, #58 to #60, #62). No doc records `doctor`, task status, project bootstrap, claim, proxy upload, completion and cloud readback succeeding together, so the runner is built, not verified live.
- **Portable sessions.** Contracts and client bootstrap merged (PR #37); every production approval gate accepts the portable `studio-user-confirmation:<client>:<gate>:<hash>:` form (PR #40). The remote MCP gateway is a separate release; Claude.ai and ChatGPT stay `read_only_untracked` until the OAuth connector exists (`docs/ENGINE_SESSION.md`).
- **Verification.** `npm run verify` runs typecheck, tests, skill validation, trigger, renderer, public-copy and no-secrets checks on Ubuntu and Windows with hash-pinned FFmpeg (`.github/workflows/ci.yml`); the control plane adds its own typecheck and 26 guards (`apps/control-plane/README.md`). At `733121f`: 519 tests pass (two pre-existing, environmental failures: ffprobe not installed). GitHub Actions was spend-blocked for part of this range (PR #61), so some of that verification is reported from a local run rather than a CI readback.

- 2026-09-07 **Portable Studio session contracts** (PR #37, `0c4b380`). Why: any supported LLM or Control Center should be a window into one engine, but "connecting this repository is necessary but not sufficient"; only a tracked gateway session grants mutation and learning capture.
