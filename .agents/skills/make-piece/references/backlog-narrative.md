The research starts with the corpus he linked to this piece on the Inspiration page, research he already pulled (Krish, 2026-10-24: a corpus is "for a specific article or a specific content piece"): `select name, drive_file_id, read_as, note_for_claude, facets from inspiration_items where kind = 'corpus' and piece_id = '<piece_id>'`; read each file in Drive (`https://drive.google.com/file/d/<drive_file_id>/view`), and its sources still pass the fact gate like any other. The end message is checked against the research before he signs it: a line the evidence does not hold changes there, never later. It is checked against the series' recent pieces too: a takeaway a recent piece already landed is never the end message again, so the new piece says what is new (Krish, 2026-10-26: "we've already done that message takeaway with the Muse versus Grok piece"). A test the piece runs is designed as an experiment before it is run: say what it tests, change one thing only (a matched control, such as the same question with only the country changed), give every tool the same access and settings, write the prompts so they need nothing outside their own words, and write down what will be read from each answer before any answer exists (Krish, 2026-10-23: "I don't think you are really thinking much about how to design a test that yields the experiment needed"). Every later step is held to it: the outline's spine is the end message, and each checkpoint is passed in order. **Drift rule:** any change to the end message, the action or a checkpoint goes back to Krish before work continues.
